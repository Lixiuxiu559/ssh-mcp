# SSH 0.2.0 重构验证设计

依据：用户授权的 Linkage UI、用户名密码同权登录、独立 MCP token、人员与调用双审计，以及工作空间三种交付方式规范。
本文件记录设计，不代表实际执行结果；最终执行结果另记录在验证报告。

| 规则与用例 | 前置条件 / 操作 | 可观察结果 | 验证入口 |
|---|---|---|---|
| R1 首次初始化 | 空身份库，无码/错误码/正确本地码分别提交 | 无码和错误码失败，正确码只创建一个用户，无默认账号，重复提交失败 | 身份存储、Web API |
| R2 凭证隔离 | 密码登录后取会话；用旧MCP token请求me，用Cookie请求MCP | 登录正常，跨用途凭证均被拒绝；缺CSRF写操作403 | Web API、实际HTTP客户端 |
| R3 人员同权 | 第一位用户创建第二位；第二位登录创建token或改服务器 | 两位启用用户均可管理，无admin字段；停用最后账号失败 | Web API |
| R4 会话撤销 | 用户登录后改密码/停用；重用旧cookie | 旧会话失效，原密码失败；停用创建者不级联停用token | 身份/API |
| R5 token迁移 | 含旧auth.users配置启动、吊销旧token、再次启动 | 原凭证首次仍可MCP调用，无网页登录权限；再次迁移不复活已吊销token | 存储、实际HTTP |
| R6 凭证并行与重启 | 创建两个token，重启后分别调用；停用其一 | 两者重启后可用；停用token的新请求/原会话拒绝，另一个仍可用 | 实际HTTP MCP |
| R7 身份审计 | 新建/改名/停用token，修改用户、资源、上传密钥；模拟失败 | 含稳定人员ID、对象ID、结果；密码、token和私钥不落库；投递故障可重试 | 存储、API、审计查询 |
| R8 MCP追溯 | 有效token执行FakeSSH命令；改名资源后查看历史 | token与目标执行时快照、命令、耗时结果可查；不保存传输正文 | 工具调用与审计 |
| R9 失败取消与重试 | 模拟断连重试、确定性SFTP失败、取消调用、审计IO失败 | 重试有尝试号；确定性错误不重试；取消不记成功；审计故障不覆盖业务结果 | pool与审计pytest |
| R10 留存与旧数据 | 放入超过30天和窗口内的人员/调用记录；无新请求清理 | 两类超期删除，身份保留；legacy记录不编造token归属，导出正确处理公式 | 审计pytest、生命周期 |
| R11 UI | 真实浏览器初始化/登录，访问服务器/人员/token/双审计，切换主题/命令面板 | 无AntD旧皮肤，实际数据，无明文token列表；键盘和窄屏可用 | 浏览器验收 |
| R12 三种启动 | 源码启动、容器启动、源码目录外安装wheel和uvx | CLI与完整前端可用，路径独立；运行数据不在安装缓存，更新不覆盖配置 | CLI pytest、打包与运行验收 |

已有测试设施为 pytest + pytest-asyncio、Fake SSH、内存 FastMCP Client 与 HTTPX ASGI。
协议认证还需实际 HTTP 服务验证；Fake SSH 不能证明真实目标网络、认证与系统命令正常。
Docker daemon 缺失时只报告构建/启动未验证，不把 Compose 配置检查等同容器运行成功。
